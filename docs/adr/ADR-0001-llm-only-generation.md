# ADR-0001：生成链路只走 LLM（无离线规则回退）

- **状态**：已接受（创始人裁决 2026-09-30「不要规则版」；实现 2026-09-30，commit e53e934）
- **上下文**：生成链路最初有双路径——LLM 生成内容 + 离线规则模板回退（无 Key 也能出实例）。创始人裁决后收敛为**仅 LLM 路径**。

## 决定

`InstanceGenerator` 只走 LLM：未配置 LLM、或输出连续两次未通过校验时，明确报错（`LLMUnavailable`），不静默降级。

## 被牺牲的东西（本 ADR 的核心栏）

1. **离线生成能力**：没有 AI Key 就无法生成新实例——「下载即用」包里的生成功能需要用户自己配 Key；
2. **零 Key 体验**：首次使用者必须先完成 AI 服务配置才能触达生成；
3. **确定性**：同一输入不再保证同一输出（模型差异/版本漂移）——质量一致性只能靠随访抽查（P-GOV-2）兜底。

## 为什么仍然这样决定

- 规则模板的内容质量天花板远低于 LLM（第一轮实测对比：LLM 版领域编排明显更好）；
- 双路径意味着两套内容质量标准与双倍维护；
- 与 NullLLM 的既有哲学一致：明确报错而非降级假象；
- 目标用户（创始人自用优先）配 Key 的成本一次性且低。

## 后果与复审触发条件

- 报错文案必须是人话 + 下一步指引（N4②，见 generate.py）；
- 若「无 Key 生成」的需求真实出现（如断网场景、Key 普惠前的大规模分发），重启本 ADR 讨论离线方案的形态；
- 复审触发：用户报告生成路径的报错体验不佳，或 LLM 成本/延迟不可接受。
