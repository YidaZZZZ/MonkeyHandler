# 外发数据清单：什么会离开这台设备

> **对应承诺**：architecture §7「最小披露」；N4③（2026-10-01 质询）要求把隐私主张变成可核对的出账流水。
> **原则**：外发的只有「生成所必需的最小集合」；打卡明细、本心卡片、危机相关内容**默认不出本机**。
> **状态：已核对（2026-10-01，含代码验证）。**

## 1. 生成训练平台时（CLI `generate` / 桌面「生成」按钮）

| 外发内容 | 来源 | 说明 |
| --- | --- | --- |
| 目标原文 | 用户输入 | 例如「二十天缓解腰背僵硬」——原样发送 |
| 画像摘要 | `user_model.summary()` | **已代码验证不含姓名**（display_name 不进 summary）；字段：目标、训练经验、每周天数、器械、伤病、睡眠、压力、时型、动机取向、坚持史、时间预算 |
| 硬约束文本 | 代码生成 | 天数、强度上限、输出格式（无个人内容） |

回传：InstanceSpec JSON（训练计划）。

## 2. 「被看见」AI 陪伴对话时

| 外发内容 | 说明 |
| --- | --- |
| 对话全文（用户主动输入 + 助手回复） | 用户主动书写/说出的话——这是该功能的目的本身，但用户应知情 |
| SEE_PROMPT（陪伴者系统提示词） | 固定文本，不含用户数据 |

回传：陪伴回复。**不外发**：本心卡片内容（生成后仅存本机）；危机关键词检测在**本机**完成，检测事件本身不外发。

## 3. 永远不外发

- 打卡明细与执行数据（RPE/疼痛/缺席——留在本机，N3 回程闭环也在本机完成）；
- 本心卡片、足迹；
- display_name（若有，从不进入任何 LLM 请求——已代码验证）；
- API Key（只发往你自己选择的服务商，用于鉴权）。

## 4. 汇总

所有外发只流向**用户自己在设置里选择的模型服务商**。平台无自建服务器。服务商的数据政策是用户与服务商之间的事，本平台的责任是：这张清单如实、可核对、随代码变更同步更新。

## 复审触发

generate.py 的 prompt 组装、user_model.summary()、被看见 SEE_PROMPT 任一变更时，本文件必须同步核对（P-GOV-4 审核门检查项）。
