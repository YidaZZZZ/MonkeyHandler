# humanity —— 人类通识知识库

> 定位：最终目标是指导「如何设计有效的、辅助用户学习训练的方案」这一实践。
> 不是百科式的知识堆砌，而是服务于训练方案设计的弹药库。

## 一、选书标准

搜集**最具影响力且公认言之有物**的关于人类的重量级著作，覆盖：

- **心理学**（动机、认知偏差、最优体验）
- **认知学**（学习科学、技能习得）
- **成功学 / 行为改变**（习惯、坚持、成就、人际影响——取其严谨者）
- **社会学**（群体、影响、承诺）
- **脑科学**（睡眠、恢复、运动与脑）
- **哲学 / 人性经典**（东西方的自我修养、人性洞察与说服智慧）
- **产品设计相邻学科**（游戏设计、人机交互、学习科学、动机心理学、行为科学与选择架构、叙事、视听反馈、服务与系统设计——书目来自 `refer/refer1.md` 报告）

影响力与「言之有物」可以冲突（如《乌合之众》影响巨大但学术上多受批评）——这正是流水线第③步存在的原因：**影响力决定它值得被处理，验证决定它的哪些主张可被使用**。

## 二、生产流水线（每本著作走一遍）

```
① 选书 → ② 总结核心思想 → ③ 逐主张交叉验证（争议不入库）
       → ④ 提取面向训练设计的提示词与方法论 → ⑤ 用户审核（入库硬门槛）
       → ⑥ 综合（synthesis/：提示词库、方法论、工作流）
```

**验证标准（已确认：逐主张验证，争议不入库）**：每个核心主张交叉验证 2-3 个独立来源，标注「支持 / 有争议 / 被推翻」；有争议的主张**不进入**提示词提取，只留在存疑区。哲学/古典类著作验证「思想影响力 + 内部自洽 + 与目标的相关性」，不适用实证复现标准的，在 verification.md 中显式说明采用何种标准。

**提取边界（2026-09-29 确认：不设事前伦理红线）**：验证只回答「主张是否可信」，不回答「是否该用」——提取不因伦理/合规预先排除任何主张；风险信息（争议点、滥用可能、证据边界）以注记形式随条目提供，**由用户在审核门逐案决定去留，审核门是唯一闸门**。

**审核规则**：⑤ 是硬门槛——未经用户审核的提取内容不得进入 synthesis/，运行时（`core/humanity.py`）只消费已审核内容。

## 三、目录与文件格式

```
humanity/
├── README.md                     # 本文件
├── refer/refer1.md               # 相邻学科书目来源（仅书目清单，其余内容不构成规范依据）
├── works/<book-id>/              # 每本著作一个目录（book-id 用英文短横线）
│   ├── work.md                   # 著作信息
│   ├── summary.md                # ② 核心思想总结
│   ├── verification.md           # ③ 逐主张验证
│   └── prompts.md                # ④ 提取的提示词与方法论
└── synthesis/                    # ⑥ 综合层（只收已审核内容）
```

| 文件 | 必填内容 |
| --- | --- |
| `work.md` | 书名/作者/年份、领域、影响力概述、选择理由 |
| `summary.md` | 核心思想（分条，每条可被独立验证） |
| `verification.md` | 逐主张：结论（支持/有争议/被推翻）+ 依据来源；文末给「入库/存疑区」清单 |
| `prompts.md` | 提取的提示词与方法论，每条标注：服务的目标（理解人类/理解用户/痴迷训练）、出处主张、状态（待审核/已审核） |
