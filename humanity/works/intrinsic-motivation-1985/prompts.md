# 内在动机与自我决定 —— 提取的提示词与方法论

> 流水线第④步产出。核心目标：理解人类 → 理解用户 → 让用户痴迷训练。
> **状态：全部「待审核」**——经用户审核后方可进入 synthesis/ 并被运行时消费。
> 注：本书为早期理论（实证结论宜配现代元分析复核），提取内容均与 SDT 2017 条目联合生效。

## 提示词

### P1 因果定向探查提示词（服务：理解用户）
「用访谈线索估计用户的因果定向：面对新计划，用户先问『这对我有什么用』（自主定向）、『别人会怎么看/不给奖励还练吗』（控制定向）、还是『反正都一样练不成』（非个人定向）？据此预判其对奖励、期限、比较的反应模式，控制定向者尤其慎用外部奖励。」
- 出处：主张 5（因果定向理论）
- 落点：`core/profiling.py` 画像采集的动机人格维度

### P2 事件信息性/控制性检查提示词（服务：痴迷训练）
「任何反馈、奖励、提醒上线前自问：用户读到的是『我做得如何』（信息）还是『系统在管我/为了奖励』（控制）？若控制性面向更显著，必须重设计或移除——同一奖励的净效应取决于哪个面向占优。」
- 出处：主张 2（认知评价理论）+ 主张 3（奖励双重面向）
- 落点：`core/motivation.py` 反馈与奖励生成约束

### P3 控制性事件审计提示词（服务：理解人类）
「枚举产品中的期限、监视感、评价压力点（如连续打卡中断提示、进度羞辱、倒计时），逐项评估是否可被感知为控制；可感知为控制且非用户自设的，重写为信息性表述或移除。」
- 出处：主张 4（控制性事件清单）
- 落点：`core/humanity.py` 知识库与硬规则（产品自检表）

## 方法论

### M1 奖励信息化改写（服务：痴迷训练）
把「做完给 X」改写为「这组数据说明你的能力变化」——奖励即胜任证据，不是交换条件；对用户已有兴趣的活动不引入预期实物奖励（过度理由效应规避说明：预期、实物、控制性奖励会在撤除后削弱内在动机）。
- 出处：主张 2、3
- 落点：`core/motivation.py` 奖励机制设计

### M2 双范式三角验证（服务：理解用户）
兴趣与坚持类判断须自报（量表/访谈）+ 行为续用（无提示下自主加练）双证据交叉；单一测量（尤其纯自报）不得作为动机结论——自由选择与自报各有混杂。
- 出处：主张 6（测量范式及其批评）
- 落点：M3 执行与再校准的数据采集规则
