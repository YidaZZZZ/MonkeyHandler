# 掌控习惯 —— 提取的提示词与方法论

> 流水线第④步产出。核心目标：理解人类 → 理解用户 → 让用户痴迷训练。
> **状态：全部「已审核（2026-09-30 创始人批准）」**——经用户审核后方可进入 synthesis/ 并被运行时消费。

## 提示词

### P1 画像采集提示词（服务：理解用户）
「探查用户的既有稳定习惯锚点（起床后/通勤/晚饭后等）、环境约束（场地、器械、家庭日程）与既往中断的具体原因（何时/何因），用于习惯叠加与默认设计。追问过去的成功启动经历，而不只问失败。」
- 出处：主张 3（环境设计）、主张 4（习惯叠加）
- 落点：`core/profiling.py` 的访谈问题设计（M2 LLM 访谈）

### P2 身份叙事提示词（服务：痴迷训练）
「以身份层而非结果层表述进度：『你正在成为不缺席训练的人』；每周用行为证据（出勤次数）而非结果指标（体重）佐证身份。禁止用羞辱或负面比较表述中断。」
- 出处：主张 5（身份叙事）——**降级标注**：叙事工具，非核心机制承诺
- 落点：计划中 Session.motivation_hook、执行闭环（M3）的反馈文案

### P3 失败恢复提示词（服务：痴迷训练）
「缺席后不惩罚、不补课、不重启整个计划：自动回落到两分钟启动版本，保护出勤链。把恢复出勤本身计为一次胜利。」
- 出处：主张 6（两分钟规则）+ 主张 7（追踪）
- 落点：执行闭环（M3）的再校准触发器

## 方法论

### M1 启动摩擦最小化（服务：痴迷训练）
每个训练节次必须给出「启动版本」（≤2 分钟：换装+热身即算完成）；装备与时段预装为默认选项（主张 3、6）。
- 落点：`domains/fitness/pack.py` 的 Session.content 设计（M1 LLM 版强制约束）

### M2 即时记录闭环（服务：痴迷训练）
完成即记录（重量/次数/时长/RPE 任选其一，强制至少一项）；记录本身构成进度可见性（主张 7；配合《心流》的即时反馈主张）。
- 落点：执行闭环（M3）check-in 设计

### M3 锚点绑定（服务：理解用户 → 痴迷训练）
新训练行为必须绑定到用户画像中的既有锚点之后（「晚饭后 → 换上运动鞋」）；无锚点可绑时先采集再生成计划。
- 落点：计划生成约束（M1 起）
