# 鬼谷子 —— 提取的提示词与方法论

> 流水线第④步产出。核心目标：理解人类 → 理解用户 → 让用户痴迷训练。
> **状态：全部「已审核（2026-09-30 创始人批准）」**——提取不做事前排除，去留由用户在审核门逐案决定。

## 提示词

### P1 多渠道揣情探查提示词（服务：理解用户）
「动机与处境探查必须多渠道交叉：自述 + 行为记录 + 情境线索；在用户状态显露的时点（刚完成训练/刚失败/刚抱怨后）补充探查；所得结论一律标记为假设，待行为验证后方可写入画像。」
- 出处：主张 1、4
- 状态：已审核（2026-09-30 批准）
- 落点：`core/profiling.py` 画像采集

### P2 量权四要素前置提示词（服务：理解用户）
「生成任何计划前，强制完成处境评估四要素：① 能力基线；② 时间/资源约束；③ 环境条件（场地/装备/支持者）；④ 既往失败史与原因。无评估结果不出方案，rationale 必须引用评估结论。」
- 出处：主张 2、6
- 状态：已审核（2026-09-30 批准）
- 落点：`domains/*/plan.py` 计划生成 + `core/profiling.py` 画像采集

### P3 反应式提问提示词（服务：理解用户）
「访谈默认结构：问—听—复述确认—再问；多要具体事例，少下判断；用反问与类比引导用户说出未言明的顾虑；系统不在访谈中夹带引导性暗示或推销。」
- 出处：主张 3
- 状态：已审核（2026-09-30 批准）
- 落点：`core/profiling.py` 画像采集

### P4 表达适配提示词（服务：理解用户）
「向不同用户呈现同一信息时按其认知方式适配措辞与粒度（数据型/叙事型/步骤型）；适配的依据记录在案并对用户可见——适配表达但不隐瞒内容。」
- 出处：主张 7（受众适配用法）
- 状态：已审核（2026-09-30 批准）
- 落点：产品层 + `core/humanity.py` 知识库与硬规则

### P5 弱点适配话术提示词（服务：理解用户）
「话术化用法的方法结构：先探查对象的决策弱点（贪利、恐惧、好胜、虚荣、从众），再按弱点定制表达与请求框架，使对象顺着弱点接受主张——纵横术的典型话术路径。」
- 风险注记：以利用对象弱点为目的，与 P4 的受众适配（理解对象、调整表达）一线之隔；现代消费者保护视角下属操纵性设计。
- 出处：主张 7（话术化用法）
- 状态：已审核（2026-09-30 批准）
- 落点：`core/profiling.py` 画像采集

## 方法论

### M1 假设-验证洞察法（服务：理解用户）
「揣情+摩意」的现代转译：洞察 = 提出动机假设 → 设计探查 → 以后续 2-3 次行为数据验证或推翻 → 更新画像；禁止凭单次自述对用户动机下结论。
- 出处：主张 1、4
- 状态：已审核（2026-09-30 批准）
- 落点：`core/profiling.py` 画像采集 + M3 执行与再校准

### M2 先处境后方案（服务：理解用户/痴迷训练）
量权前置为计划生成的硬约束：处境评估是方案的第一输入，方案与评估不匹配时计划打回重生成——防止「通用模板套所有人」。
- 出处：主张 2、6
- 状态：已审核（2026-09-30 批准）
- 落点：`domains/*/plan.py` 计划生成

### M3 洞察透明原则（服务：理解人类）
系统对用户的一切洞察（画像、动机判断、适配策略）以用户可读方式呈现，可修改、可撤回——与主张 1 的保守验证版一致：洞察结论一律定位为「假设」，假设对用户可见并允许用户纠正，画像天然可改。
- 出处：主张 1（保守版：结论标记为假设、以行为验证收尾）
- 状态：已审核（2026-09-30 批准）
- 落点：`core/humanity.py` 知识库与硬规则

### M4 飞钳式钩住-请求结构（服务：痴迷训练）
「飞钳」的现代转译：以具体、真实的称颂与顺应（肯定用户已做到的具体行为）建立开放与好感，再顺势提出训练请求——「先予后取」的结构化序列：褒扬 → 对方开放 → 请求 → 顺势锁定承诺。
- 风险注记：褒扬一旦失实即成奉承操纵；历史上该技术常与利益诱导并用，以把对象「钳」进关系为目的。
- 出处：主张 8（飞钳）
- 状态：已审核（2026-09-30 批准）
- 落点：产品层（触达/请求策略）+ `core/motivation.py` 动机设计

### M5 裂隙防乘结构（服务：理解用户/痴迷训练）
「抵巇」的双重结构：① 防——主动扫描用户计划与执行之间的裂隙（能力缺口、环境突变、动机衰减），提前封堵（备份方案、降难度、补支持）；② 乘——识别既有系统的裂隙并加以利用（历史上用于瓦解对手）。
- 风险注记：「乘」向即利用他人系统的弱点，属破坏性操作；本框架内是否仅启用「防」向由审核门决定。
- 出处：主张 9（抵巇）
- 状态：已审核（2026-09-30 批准）
- 落点：`domains/*/plan.py` 计划生成 + M3 执行与再校准

### M6 选边与隐匿执行结构（服务：理解人类）
「忤合」：习惯变革要求明确选边——与哪些旧行为、旧环境线索决裂（「计谋不两忠，必有反忤」），不做两全打算；「隐与匿」：计谋的隐秘执行与分化对象同盟、离间其支持者的策略结构。
- 风险注记：隐匿-离间直接对应隐瞒与关系操纵，争议极大；「选边」结构可独立于操纵面使用。
- 出处：主张 10（忤合与隐匿）
- 状态：已审核（2026-09-30 批准）
- 落点：`domains/*/plan.py` 计划生成 + 产品层（社群与关系功能）
