# 心流 —— 提取的提示词与方法论

> 流水线第④步产出。核心目标：理解人类 → 理解用户 → 让用户痴迷训练。
> **状态：全部「待审核」**——经用户审核后方可进入 synthesis/ 并被运行时消费。

## 提示词

### P1 难度校准提示词（服务：痴迷训练）
「校准下一次训练难度，使目标成功率落在心流通道：连续成功 >90% 提高难度一档；<70% 降低难度一档；每次调整必须在计划 rationale 中说明依据。默认启发值 85%，须随用户自报数据持续校准。」
- 出处：主张 3（心流通道）——精确数值部分为启发式，标注可校准
- 落点：`core/motivation.py` 的 `adjust_difficulty`（已实现），M3 接入再校准

### P2 训练节次三问提示词（服务：痴迷训练）
「设计每次训练时必须回答三问：① 本次的清晰目标是什么（一句话可陈述）？② 用户在哪个环节获得即时反馈（重量/次数/时间/RPE，至少绑定一项）？③ 挑战相对用户当前能力处于什么位置？」
- 出处：主张 2（触发三要素）
- 落点：计划生成约束（`Session.objective/motivation_hook` 已承载雏形，M1 LLM 版强制）

### P3 心流画像探查提示词（服务：理解用户）
「探查用户既往『忘记时间』的活动场景与条件（何事/何地/独自或与谁/反馈来自哪里），定位其心流触发模式，映射到训练场景（如：量化反馈型/对抗型/节奏型）。」
- 出处：主张 1（现象学）+ 主张 7（主动活动）
- 落点：`core/profiling.py` M2 访谈的探查维度

## 方法论

### M1 反馈通道强制（服务：痴迷训练）
每个训练动作必须绑定一个可即时记录的量化信号；**无信号的练习不进入计划**——这是「即时反馈」的工程化落地。
- 出处：主张 2、7
- 落点：领域包 build_plan 的内容设计约束（M1 起）

### M2 挑战螺旋与能力证据（服务：痴迷训练）
每期计划结束必须产出「能力证据」（完成重量/时长/动作等级），它同时是：下一期难度输入（心流通道上移）+ 身份叙事素材（与《掌控习惯》P2 衔接）。
- 出处：主张 3（动态平衡）
- 落点：执行闭环（M3）的周期结算

### M3 主动结构优先（服务：痴迷训练）
优先设计需要用户主动参与的结构（选择、执行、记录、复盘），而非被动接收（推送、打卡提醒轰炸）——被动结构不产生心流且加剧精神熵。
- 出处：主张 7 + refer1.md「主动活动悖论」
- 落点：产品层（提醒/推送策略）与工作流设计的边界约束
