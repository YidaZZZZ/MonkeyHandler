# 这才是服务设计 —— 核心思想总结

1. **服务是过程不是物件**：服务随时间展开，用户经历的是一系列触点（touchpoints）的序列——设计对象是完整旅程，不是单个界面。

2. **服务蓝图分层**：前台（用户可见的触点）、后台（不可见但支撑体验的员工/系统动作）、支撑过程（政策、IT、基础设施）必须画在同一张图上——前台体验问题常是后台责任缺失的表象。

3. **前后台一致性**：用户可感知的每个承诺都需要后台动作兜底——「界面漂亮、后台不履约」是服务失败的典型形态。

4. **以研究开始**：服务设计从情境观察与访谈（而非方案想象）开始，研究产出是旅程图与痛点地图。

5. **共同设计**：让用户、一线员工与决策者一起参与设计——一线员工掌握后台真实约束，共同设计提高方案可实施性。

6. **服务原型**：上线前用低保真原型（桌面演练、角色扮演、假门测试）验证旅程与前后台协作——原型阶段的失败成本远低于上线后。

7. **测量连接体验与运营**：体验指标（满意度、任务成功）必须与运营指标（时长、错误率、等待）连接观察，否则局部优化损害整体。
