# 驱动力 —— 提取的提示词与方法论

> 流水线第④步产出。核心目标：理解人类 → 理解用户 → 让用户痴迷训练。
> **状态：全部「已审核（2026-09-30 创始人批准）」**——经用户审核后方可进入 synthesis/ 并被运行时消费。

## 提示词

### P1 自主选项提示词（服务：痴迷训练）
「每期计划必须包含至少一处真实选择：动作替换表、训练时段、练习方式或难度路线任选其一；选项必须实质不同而非形式摆设；用户的选择记录回写画像用于下次计划。」
- 出处：主张 3（自主）
- 落点：`domains/*/plan.py` 计划生成 + `core/profiling.py`

### P2 目的访谈提示词（服务：理解用户）
「探查训练对用户的意义层次：为谁而练、练成之后想做什么、与自我叙事的关系；把目的语句（用户原话）写入计划 rationale，在关键节点用其原话回扣。」
- 出处：主张 5（目的）
- 落点：`core/profiling.py` 画像采集 + `domains/*/plan.py`

### P3 奖励形态三问提示词（服务：理解人类）
「上线任何奖励机制前过三问：① 是否事先承诺？② 是否以表现/坚持为给付条件？③ 是否实物/权益形态？——三项同时命中即重新设计；改用事后意外肯定或信息性反馈（『本周比上周多完成 2 次』）。」
- 出处：主张 2、7（削弱效应及其边界）
- 落点：`core/motivation.py` 动机设计 + `core/humanity.py`

### P4 能力感证据呈现提示词（服务：痴迷训练）
「进度呈现一律以用户自身历史为参照的能力证据（重量/时长/动作等级的纵向对比），禁止与他人排名作为主进度视图；『在意的领域正在变好』是本条的心理依据。」
- 出处：主张 4（能力感部分）+ 主张 3（自主/胜任）
- 落点：`core/motivation.py` + 产品层

## 方法论

### M1 奖励形态白名单（服务：理解人类）
奖励只建议两种形态：① 完成后的意外性肯定（非事先承诺）；② 信息性反馈（告诉用户做得如何、为何有效）。预期性、有条件、实物性的奖励三件套建议默认不采用，例外逐案提交审核（设计建议，已审核（2026-09-30 批准））。
- 出处：主张 7 + verification.md 主张 2 边界
- 落点：`core/humanity.py` + 产品层

### M2 公平前提检查（服务：理解用户）
在动机机制设计前先检查基础层：用户投入（时间/金钱）与所得是否被感知为公平；感知失衡时优先修复基础层而非叠加激励。
- 出处：主张 8（「足够」门槛）
- 落点：产品层 + M3 执行与再校准（用户流失访谈检查项）

### M3 目标-目的双轨写入（服务：理解用户）
每期计划文件同时承载：可验证的能力目标（专精轨）与用户的目的语句（目的轨）；执行复盘时两轨各结算一次——只报目标达成不报目的回扣，视为计划未完成复盘。
- 出处：主张 4（能力感）+ 主张 5（目的）
- 落点：`domains/*/plan.py` + M3 执行与再校准
