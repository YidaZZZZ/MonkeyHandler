# 意图层：构筑指导 Prompt

> 用途：**构筑期**——在设计平台功能时，把设计决策写成可评审、可证伪的意图。与 `humanity/synthesis/prompts/`（运营期）相互独立。
> **状态：全部草稿·待审核。** prompt 引用的方法论以 [methodology-map.md](methodology-map.md) 为准。

## P-INT-1 意图登记

**目的**：把一个设计决策写成五层意图 + 登记表行（守护：意图可解释、可证伪）。

```text
你是意图登记员。把下述设计决策整理为一条意图记录（INT-xx），必须包含五层：
1. 存在性理由：解决谁的什么真实问题？证据是什么（访谈/数据/著作条目 works/<id>）？
   无证据的部分标注「待调研」，禁止编造。
2. 价值与权衡：它同时服务谁？与哪条既有意图存在张力？
3. 设计原则：引用 1-3 条著作原则（附条目出处与证据等级）。
4. 模式与置信度：采用什么模式，置信度几何（对应 works verification 证据分级）。
5. 形式映射：中间变量 → 形式变量 → 可测推论。
末尾必须给【反证条件】（什么数据出现即推翻本意图）与【复审触发条件】。
输出：意图登记表一行（Markdown 表格行）。
```

## P-INT-2 权衡与 ADR

**目的**：张力发生时，产出决策记录而不是和稀泥（守护：被牺牲的东西必须显式）。

```text
你是决策记录员。下述两条意图发生张力，请产出一份 ADR：
1. 陈述冲突双方及其各自依据（引用意图 ID 与著作原则）；
2. 列出全部候选方案及各自代价；
3. 给出推荐选择与理由——解法优先考虑「分层」而非「折中」
   （默认路径/受限路径/专家路径各司其职）；
4. 明确写出【被牺牲的东西】——没有这一栏等于没有权衡；
5. 验证指标（含反指标）与复审触发条件。
平台默认排序规则（若用户未另行裁定）：G1 长期依从 > G2 掌握真实 > 操作效率 > 视觉简洁；
恢复预算硬规则例外优先。
```

## P-INT-3 原则溯源

**目的**：设计原则必须挂著作出处，防止审美口癖混入裁判规则（守护 F29 知识纪律）。

```text
对下述设计原则逐条溯源：
- 在 humanity/works/ 中找到支持它的著作与「已入库」主张（引用 verification 结论）；
- 标注证据等级（强/中/低/待复核）；
- 找不到出处的原则：标注「待调研——暂不得用于裁决」，不得降格为「常识」直接使用。
输出：原则清单（原则 | 出处 | 等级 | 用法边界）。
```

## P-INT-4 形式映射

**目的**：把抽象原则落成可观察变量，保证意图可被数据检验。

```text
对下述意图完成形式映射：
1. 声明中间变量（如：成功率、RPE、依从率、调节类型迁移）——必须是可测量/可自报的；
2. 声明形式变量（界面上可见、代码可实现的东西）；
3. 写出机制假设（为何该形式能改变该中间变量——引用著作依据）；
4. 写出可测推论（可被埋点或实验验证的预测，含方向与幅度量级）。
若写不出中间变量：该意图暂不可进入细节层，退回 P-INT-1 补全。
```

## P-INT-5 张力与涌现扫描

**目的**：新意图入库前，与既有意图做协作/张力扫描；防止细节层被迫消化意图层矛盾。

```text
给定新意图 INT-xx 与既有意图登记表：
1. 协作：它能同时支撑哪些既有意图？（高质量信号）
2. 张力：与哪些意图冲突？冲突是可分层化解还是必须取舍？
3. 涌现风险：它依赖的上级意图是否自身一致？（一个细节别扭，往往是上一级
   意图不一致——若发现，指出应修改的上级意图而非本意图）
输出：关系清单 + 需要生成 ADR 的张力项列表。
```
