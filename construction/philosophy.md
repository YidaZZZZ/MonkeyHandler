# 产品理念：让用户对「自我提升」上瘾

> **状态：已审核（2026-09-30 批准）。**
> **来源**：2026-09-29 用户定义——产品的理念是让用户提升的爽、一直提升；设计上要让用户对自我提升上瘾。本文把前述 36 本著作中可复用的方法论收敛到这一目标上，形成构筑层的理念源（向下传给 intent / profiling / detail）。

## 〇、内核与呈现的分离（2026-09-29 用户澄清，最高优先级的呈现纪律）

**平台的内核思想，与给用户呈现出的效果和传递的影响，不是一回事。** 内核（著作方法论、意图基线、硬规则、数据飞轮、构筑体系）负责「为什么有效」，呈现负责「用户感受到什么」——内核必须**体现为体验的品质**（难度刚好、反馈及时、进步可见、值得信任），而不是被讲述出来。把内核内容大量呈现给用户反而引起反效果：术语疏远用户、暴露设计机制、瓦解体验的权威感。

**纪律：终端用户界面不出现内核词汇**——works/xxx 条目 id、u_xxx、CUP/CWI/CWD、S/R/C/ST、recovery_budget、因素网 F-编号、元平台/阶段性产物/数据飞轮/本地迭代、tier 裁剪、文件路径引用（construction/…、docs/…）等，一律不出现在用户可见的界面文字中。

**转译而非省略**——内核概念以用户语言的效果呈现：

| 内核概念 | 用户看到的 |
| --- | --- |
| 恢复预算硬规则 | 「昨晚睡得少，今天自动安排了轻量版」 |
| 数据飞轮 / 本地迭代 | 「你的数据只保存在这台设备上，用来让下一期更贴合你」 |
| 证据链画像 | 「根据你告诉我们的」 |
| 心流通道 85% | （不解释——直接让难度刚好） |
| 缺席回落（两分钟规则） | 「中断后第二天只要求两分钟，先回来再继续」 |
| 成瘾对象错位复核 | （后台运行，用户不可见） |

**内核的呈现对象是构建者与审核者**：仓库文档（docs/、humanity/、construction/）与审核门是内核的呈现面——两个受众，两个界面，互不越界。

**机制叙事禁令（N9，2026-10-01 质询）**：泄漏不止于词汇——整页向终端用户解释设计机制（如飞轮叙述、「为什么它会越来越懂你」）同样违反本条：每个词都合规，整页却在讲内核。机制只允许两种形态出现在用户面前：**体验品质本身**，与**真实的数据证据芯片**（「本期调整引用了你上期的 3 次缺席记录」）。「越来越懂你」tab 的形态随 D10 重审。

**「为什么」解释层**：用户主动想了解时（如「为什么练这个」），给**人话版**依据（效果导向：这个动作对你的目标意味着什么），仍不暴露内部 id 与文件路径；安全类信息永远用最直接的用户语言。

## 一、理念陈述

**上瘾对象 = 自我提升本身**（能力真实增长的可感知体验），而不是打卡、奖励、或 app 机制。

一句话：**让「变强」这件事成为最强的强化物。**

著作库的收敛依据：
- 胜任感来自可见进步，是最强的动机来源（`u_progress_competence`：Bandura 1997；Amabile & Kramer《The Progress Principle》；Harkin 2016 元分析——监控即促进）；
- 心流的愉悦来自「刚好够到又够到了」的挑战（`u_flow_challenge`，works/flow）；
- 掌控的愉悦发生在**练习当下**，而非事后奖励（works/game-feel：输入-响应-情境-润色）；
- 胜任是基本心理需求，其满足本身就是奖赏（works/self-determination-theory）。

与「不做事前红线」的关系：这不是一串禁令，而是**目标函数**——把强化物从机制侧搬到提升侧；外部奖励、紧迫结构、留存钩子等机制仍可复用（它们在著作库中已入库），用作提升体验的放大器，取舍由审核门逐案决定。

## 二、可复用的方法论（爽的七个构件）

| 构件 | 方法论 | 来源 | 构筑落点 |
| --- | --- | --- | --- |
| 1. 爽的原材料 = **真实的进步** | 渐进超负荷、刻意练习、间隔与检索 | peak、make-it-stick | 训练内容必须产生真实能力增量——**假进步喂不出真爽**，这是整座大厦的地基 |
| 2. 爽的呈现 = **进步被看见** | 进步可见/监控/进步原则 | u_progress_competence、Harkin 2016 | 每次访问先看见「比上周的自己」：对比、曲线、能力证据（呈现形式的第一性要求，见 §三） |
| 3. 爽的当下 = **即时反馈与掌控感** | 心流三要素、手感四要素 | flow、game-feel | 训练中每个动作绑定量化信号；完成即记录，反馈 100ms 级 |
| 4. 爽的节奏 = **心流通道** | 目标成功率约 85%，随数据移动 | flow、peak | 难度校准（`adjust_difficulty`）：一直「差点够到、又够到了」——一直爽 |
| 5. 爽的节拍 = **现时偏差对策** | 即时回报密度、习惯追踪 | atomic-habits、misbehaving | 每节次自带即时可感知回报；远期收益（能力、体态）被可视化逐步显影 |
| 6. 爽的记忆 = **能力证据沉淀** | 逆向设计（能力证据先于活动）、知行合一 | understanding-by-design、chuanxilu | 每周期产出「我现在能做到什么」——既是下期难度输入，也是身份叙事素材 |
| 7. 爽的个体差异 = **爽点画像** | 动机取向决定钩子选型 | d_motivation_orientation（works 各书收敛） | 数据型看曲线、叙事型看身份、社交型看同伴、竞争型看比分——profiling 供数，detail 呈现 |

## 三、呈现形式的第一性要求（按平台分层，2026-09-29 澄清）

主平台与产物平台**共用同一套层级**（价值观/意图/细节三层均适用），但**主目标侧重不同**——因此呈现形式的要求按平台分层：

- **主平台（呈现与生产）**：**首屏定律适用**——用户打开主平台主页面，第一眼看到的是自己的提升轨迹（跨实例汇总）与平台的生产成长（知识资产、数据飞轮）；当下的训练进程可以呈现，但**不能占据主导**——训练进程的主呈现场在产物平台。主平台呈现什么、以什么方式呈现，倚仗主平台自己的生成理念（本文件 + construction/intent 的意图基线）。
- **产物平台（专项训练界面）**：**训练进程主导**——第一屏是今天的训练本身；提升痕迹作为支持性信息呈现（次级位置，不占据主导）；完成动作的反馈含义化（「这意味着什么提升」）保留在训练流内——爽在练的当下发生。
- **爽必须真实**（两个平台通用）：呈现与真实数据一一对应（信任资产 F28）；空心爽会被 R4 复核识别，属于成瘾对象错位（见 §四）。

## 四、成瘾对象的错位风险（审核参考，非禁令）

理念的目标是把成瘾锚在「提升」上；以下是锚错位的信号，作为 R3/R4 回路的复核证据走 P-GOV-1/2，取舍在审核门：

| 错位 | 表现 | 检测信号 |
| --- | --- | --- |
| 对机制上瘾 | 为打卡而打卡，出勤但能力不涨（空心依从） | 打卡 ↑ 而能力证据不 ↑（R4） |
| 对奖励上瘾 | 没有奖励就不练 | 调节类型迁移停滞或倒退（self-determination-theory） |
| 对内容爽但没变强 | 过程愉快、测评不达标 | 周期结算能力证据不达标（P-GOV-1） |

## 五、对构筑对象的影响

- **intent/**：本理念列为**战略意图第一位**（表述：让提升本身成为强化物），高于具体机制决策；G1×G2 仍是结果变量，本理念是产生它们的发动机；主平台与产物平台各自的三层意图基线都从本理念出发，仅主目标侧重不同；
- **profiling/**：把「每个人的爽点」画像化——d_motivation_orientation 之外，补充「进步敏感通道」（数据/叙事/社交/竞争）的持续校准；
- **detail/**：两个平台各自按 §三 的分层要求进入界面意图与规格评审门禁；
- **demo/**：已部分体现（progress 钩子、完成即记录、85% 通道）；首屏主导权已按 §三 修正——训练进程主导，提升痕迹降为辅助位。
