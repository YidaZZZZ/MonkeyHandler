# profiling —— 对用户的个性化了解（构筑策略）

> **定位**：平台三大构筑对象之一。意图层/detail 层构筑的是「系统长什么样、为什么」，本目录构筑的是「系统如何理解这一个用户」——即识人子系统的产能：人性知识库（已建）→ 采集引擎 → 个体画像。
> **理念**：个性化了解不是「填一张表」，而是一条持续的证据链：多渠道揣情 → 带证据入档 → 行为数据持续校准。画像质量直接决定计划生成的匹配度（因素网 F20）。
> **状态：草稿·已审核（2026-09-30 批准）。** 采集的方法论依据见 [methodology-map.md](methodology-map.md)。

## 构筑对象与现状

| 组件 | 内容 | 代码现状 |
| --- | --- | --- |
| 人性知识库 | 共性 + 个体差异维度（差异维度必带 measure） | ✅ `core/humanity.py`（内核 15 条） |
| 采集引擎 | 通用核心问题集（6 题，知识库派生，每题带 decision_point）+ 领域包补充；问卷 → M2 自适应访谈 → M3 行为校准 | ✅ 问卷版 `core/profiling.py`；访谈/行为待建 |

| 画像消费 | `summary()` 最小披露喂给计划生成；缺口（open_questions）回流采集 | ✅ 接口已有 |

## 构筑策略（分期）

1. **问卷通道打磨**（M0-M1）：核心问题集的 decision_point 审计；答案→画像的置信度标定；与领域包问题的拼装顺序（通用先、领域后、按需补问）。
2. **自适应访谈**（M2）：问卷升级为对话（LLM），追问/澄清/按差异维度探查；访谈中数值题走反锚定顺序；每轮产出结构化画像更新（P-PRO-1，见 synthesis/prompts）。
3. **行为校准**（M3）：check-in 与执行数据回流画像；自报与行为冲突时以行为为准并降自报置信度；缺口语ently回流为下一轮采集目标。
4. **画像消费验收**：任意一次计划生成的 rationale 必须能引用到画像事实（key 级）——这是本子系统的验收线。

## 与其他构筑对象的关系

- → **intent/**：意图登记的「事实前提」证据由本子系统供给（用户是谁、怕什么、会怎么错）；
- → **detail/**：采集/check-in 界面属于细节层规格，但其话术与方法论（不评判、反锚定、四段式反馈）来自本目录映射；
- → **识域（不设构筑策略）**：按 2026-09-29 决定，专业方法调研不设构筑策略——领域知识由大模型常识 + 专业调研直接产生（demo 中已标注常识边界）。
