# profiling：构筑指导 Prompt

> 用途：**构筑期**——建造/验收「对用户的个性化了解」子系统时使用。运营期访谈提示词见 `humanity/synthesis/prompts/profiling.md`。
> **状态：全部草稿·已审核（2026-09-30 批准）。**

## P-UPF-1 采集问题审计

**目的**：任何进入问卷/访谈的问题，先过最小提问原则与知识库溯源。

```text
对下述采集问题逐条审计：
1. decision_point：它将改变计划/界面的哪个决策？写不出 → 建议删除或合并；
2. 知识库溯源：它测的是哪个差异维度（based_on）？维度在人库中是否带 measure？
3. 反锚定检查：数值题是否先自报后确认？选项是否有诱导性预设？
4. 措辞检查：是否有评判性措辞（「你为什么不能坚持」→ 改行为链问法）？
输出：问题清单（问题 | decision_point | based_on | 判定 | 修改建议）。
```

## P-UPF-2 证据链检查

**目的**：画像写入与消费的证据纪律验收。

```text
对下述画像数据/代码路径逐项核对：
1. 每条事实是否携带 Evidence（来源/详情/置信度/时间）？无证据写入是否被拒绝？
2. 置信度是否随证据更新（新证据追加而非覆盖）？
3. 自报与行为冲突的处理路径：是否以行为为准并降自报置信度？
4. based_on 是否指向真实存在的知识库条目？
5. 对外披露（summary）是否最小化（无身份信息、只发事实）？
输出：核对表 + 缺口清单。
```

## P-UPF-3 缺口回流设计

**目的**：画像缺口必须变成下一轮采集目标，而不是被遗忘。

```text
对下述画像与计划生成日志：
1. 列出本次生成中「画像缺失但被保守默认值顶替」的字段；
2. 为每个缺口设计补采问题（过 P-UPF-1 审计）；
3. 排序：按「对计划决策的影响大小」排出下一轮采集优先级。
输出：补采清单（问题 | 影响 | 时机——下次 check-in / 下次计划前 / 立即）。
```

## P-UPF-4 画像消费验收

**目的**：本子系统的验收线——计划 rationale 必须能引用到画像事实。

```text
给定一份计划及其 rationale：
1. 标出 rationale 引用的每个画像 key，核对其在画像中真实存在且置信度达标；
2. 标出「理应影响计划却未被引用」的画像字段（漏用）；
3. 标出「被引用但证据薄弱」的字段（误用）。
输出：引用矩阵（key | 是否存在 | 置信度 | 被引用处 | 判定）。
```
