## 编号体系（任何字段可用短码互引）

`S-xx` 界面｜`R-xx-xx` 区域｜`C-xx` 组件｜`ST-xx` 状态｜`E-xx` 交互事件｜`F-xx` 反馈｜`P-xx` 流程｜`T-xx` 测试标识｜`M-xx` 埋点｜`INT-xx` 意图（上游）

## L0 · 范围与依赖（先写死边界，防蔓延）

系统名称/版本、目标用户与角色（含能力差异）、目标平台与端、本次纳入范围、**本次明确不做**、上游依赖（接口/契约/Mock）、下游依赖（埋点/风控/推送）、合规与标准（目标 WCAG 等级——建议 AA，须确认）、已知约束（性能预算/技术栈/工期）。

## L1 · 结构层：界面 → 区域 → 组件 → 状态

- **S 界面**：编号、名称/类型、访问路径、出现条件、包含区域与组件、布局断点、初始化数据、离开条件、埋点。
- **R 区域**：语义角色（地标）、标题与可访问名称、视觉范围、响应式行为、内含组件清单。
- **C 组件**：**只定义一次、多处引用**；编号、组件族、可访问语义（原生元素优先）、视觉形态、**状态全集**、子结构、内容规则、可配置项、数据契约、稳定 test-id（T-xx）。
- **ST 状态**：状态名（默认/悬停/聚焦/按下/激活/选中/加载/成功/失败/空/禁用/只读/部分选中）、触发条件、**四处表达**（视觉/文案/可访问性/焦点）、互斥与共存。状态集合先在组件层统一定义（速查表），界面层只引用。

## L2 · 行为层：一次交互 = 一个事件

**E 事件六字段**：触发（方式/对象热区/参数）— 约束（前置条件/校验/频率）— 过程（同步异步/节流/可中断）— **结果（成功/失败/超时/中断/重复触发五种，缺一不可）** — 反馈（引 F-xx）— **可撤销性**（可否撤销/重做、窗口期、方式）；另含焦点迁移、异常分支、埋点。

**F 反馈**：类型—载体—时长—可关闭性；信息层级（成功/信息/警告/错误/破坏性确认）；无障碍（politeness/assertive、聚焦处理）；**降级策略**（读屏/老年机/超大字体）。

**P 流程**：起点→触发→分支→终点四段式；主成功路径/替代路径/异常与恢复/退出与返回/漏斗埋点。

## 横切面

1. **输入通道**：鼠标触控/键盘/焦点管理/读屏/语音手柄——**逐通道显式声明支持或不支持**，不支持的写原因与降级；
2. **内容与文案**：真实文案（零占位符）、变量与格式、空值/截断规则、可访问名称（可与视觉文案不同）、本地化；
3. **视觉与动效**：设计令牌（色/字/圆角/动效曲线与时长）三要素可被代码复现；主题与模式；数据密度；适配（折叠屏/分屏/安全区）。

## 质量与门禁

- **阈值（建议值，须团队确认后定稿）**：操作 100ms 内可见反馈；滚动动效 60fps；主流程成功率分渠道达标；WCAG AA；组件状态覆盖 100% 命中组件库；关键交互有稳定 test-id；文案零占位符零硬编码；离线/弱网/无 JS/缩放/读屏五类降级通过。
- **评审门禁**：需求→交互→视觉→技术→可访问性→测试准入→上线准入，逐道有通过条件。
- **自检十条**（写完必问）：界面出入条件？状态全集？四处表达？事件五种结果？四条路径？四通道声明？真实文案？令牌可复现？埋点定义？变更可反向定位？
- **变更追溯矩阵**：需求/约束 ↔ 界面 ↔ 组件 ↔ 事件 ↔ 状态/反馈 ↔ 用例 ↔ 埋点，双向可达。
