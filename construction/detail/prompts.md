# 细节层：构筑指导 Prompt

> 用途：**构筑期**——把冻结的意图基线落成可判决的交互规格。与 `humanity/synthesis/prompts/`（运营期）相互独立。
> **状态：全部草稿·已审核（2026-09-30 批准）。** 方法论依据见 [methodology-map.md](methodology-map.md)。

## P-DTL-1 事件穷举

**目的**：把一个组件/流程的行为拆成完备的事件集（守护：五种结果 + 可撤销性不遗漏）。

```text
你是交互规格撰写员。对下述组件/流程穷举交互事件（E-xx），每个事件必须填全六字段：
触发（方式/热区/参数）— 约束（前置/校验/频率）— 过程（同步异步/可中断）—
结果（成功/失败/超时/中断/重复触发五种，逐项写明转入的状态）— 反馈（引 F-xx）—
可撤销性（可否撤销/重做、窗口期、方式；破坏性操作必须给撤销路径）。
另附：焦点迁移（失焦去哪、返回回哪）、异常分支（网络/权限/冲突/重复提交）、埋点（M-xx）。
依据：失败安全（works/rules-of-play）、响应阈值（works/game-feel）。
输出：事件明细表（Markdown 表格，一行一事件）。
```

## P-DTL-2 反馈规格

**目的**：每条反馈可被开发直接实现、被测试逐条断言。

```text
为下述事件集设计反馈（F-xx），每条定义：类型（行内/状态栏/轻提示/确认弹层/页面）、
信息层级（成功/信息/警告/错误/破坏性确认）、载体规范（色/图标/位置/时长——
听觉载体按「状态→音高/节奏/时长映射表」给出，禁止所有提示同一音效）、
交互要求（可否关闭/是否阻塞）、无障碍（politeness/assertive、聚焦处理）、
降级策略（读屏/无震动/超大字体）。
错误类反馈一律四段式：发生了什么—为什么—如何修复—如何撤销（works/design-of-everyday-things）。
每条反馈注明其绑定的量化信号（若无，标注「该练习无即时信号」供上游复核）。
```

## P-DTL-3 状态×异常交叉

**目的**：用笛卡尔积扫出遗漏状态（守护：状态全集完备）。

```text
对下述组件：先列出状态全集（默认/悬停/聚焦/按下/激活/选中/加载/成功/失败/空/
禁用/只读/部分选中——裁剪为本组件实际可能的集合），再与场景状态交叉
（空/加载中/部分加载/加载失败/断网超时/无权限/数据过期/并发冲突/输入非法/
系统降级维护）。交叉表中每个格子写：视觉表现｜文案｜可重试性｜埋点。
格子内容与相邻组件重复时引用组件库定义（C-xx），不重写。
依据：偏差是情境的产物——每个场景状态单独声明，不做默认假设（works/misbehaving）。
```

## P-DTL-4 多通道声明

**目的**：同一功能在不同输入方式下等价可用，不允许默认假设。

```text
对下述功能集，逐通道显式声明支持或不支持（不支持的必须写原因与替代/降级）：
鼠标触控（含手势与替代方案）、键盘（Tab 顺序/Enter/Space/方向键/Esc/快捷键冲突）、
焦点管理（初始焦点/焦点陷阱/失焦恢复/固定元素遮挡）、屏幕阅读器（角色/名称/值/
状态通报策略）、语音手柄眼动（按目标平台能力）、缩放与字体（200%/超大字/横竖屏）。
多通道冗余原则：一条消息一个主通道，关键消息多通道冗余；冗余服务于可达性
（works/auditory-display、works/game-sound）。
```

## P-DTL-5 自检与门禁

**目的**：规格写完后的最小完备性验收。

```text
对下述规格文档逐条执行：
1. 自检十问（界面出入条件/状态全集/四处表达/事件五种结果/四条路径/四通道声明/
   真实文案/令牌三要素/埋点定义/变更反向定位）——逐问给「通过/不通过+证据」；
2. 质量阈值核对（100ms 反馈/60fps/成功率/WCAG AA/组件状态覆盖/稳定 test-id/
   零占位符/五类降级）——阈值尚未经团队确认的，标注「建议值待定稿」；
3. 意图追溯核对：每条规格条目是否挂到 INT-xx？挂不上的标出，回到意图层补登记
   或删除该条目。
输出：门禁报告（逐项结论 + 缺口清单）。
```
