# 平台构筑：构筑对象与顺序

> **产品理念（理念源，2026-09-29/30 确立）**：让用户提升的爽、一直提升——**让用户对「自我提升」本身上瘾**，上瘾对象是提升而非机制。方法论复用与各层下传见 [philosophy.md](philosophy.md)。
> **产品初衷（2026-09-29/30 对话确立）**：做一个有无限耐心、永不评判的陪伴者——先接住迷失的人（[被看见](being-seen.md)，心理侧），再把他们一小步一小步带回世界（技能侧）。目标人群：低心力、高敏感人群（含抑郁、发作性睡病等境遇）。
> **来源**：`humanity/refer/refer2.md`（交互系统的三层结构对话）+ `humanity/refer/用户界面交互系列工程拆解规格模板.docx`（细节层完备规格框架）。
> **构筑顺序**：意图层 → 细节层 → demo；「对用户的个性化了解」（profiling）为并行构筑对象——其产出是个体画像，同时是意图层事实前提与计划生成的输入。
> **修订记录**：2026-09-29 创建；同日 refer1.md 删除、新增 profiling 构筑策略、产出初版交互 demo、确立产品理念；2026-09-30 新增「被看见」常驻功能（主平台心理侧，见 [being-seen.md](being-seen.md)）。

## 构筑对象全景

```
construction/
├── profiling/   对用户的个性化了解（识人子系统）构筑策略 ← 著作中「识人维度」方法论的指向地
├── intent/      意图层（为什么是这个样子）—— 事实前提证据由 profiling 供给
├── detail/      细节层（可判决的完备规格）→ demo
├── demo/        初版交互 UI demo（20 天脊柱侧弯运动与拉伸）
└── values/      价值观层（暂不构筑，空占位）
```

- **意图层**回答「为什么是这个样子」：五层意图结构 + 推导链（必须有反证条件）+ 三张表（登记表/ADR/追溯矩阵）。规格是判决性的，意图是解释性的。
- **细节层**回答「做成什么样子」：两个合格执行者拿同一份文档能实现出可观察行为等价的产品（S/R/C/ST 结构 + E 事件 + F 反馈 + 多通道 + 门禁自检）。
- **profiling**回答「系统如何理解这一个用户」：人性知识库 → 采集引擎（问卷→自适应访谈→行为校准）→ 带证据的个体画像；验收线 = 计划 rationale 可引用到画像事实。
- **values**（使命/立场/伦理）暂不考量，仅空目录占位。
- **识域（专业方法调研）不设构筑策略**（2026-09-29 决定）：领域知识由大模型常识 + 专业调研直接产生（M2 的 ResearchEngine），demo 中已显式标注常识边界。
- **层级一致性（2026-09-29 澄清）**：主平台与产物平台**共用同一套层级**（价值观/意图/细节三层均适用），只是主目标侧重不同——主平台侧重**呈现与生产**（其主页面以提升轨迹与生产成长为主导呈现，训练进程可呈现但不占主导），产物平台侧重**训练执行**（训练进程主导，提升痕迹为辅助呈现）。

## 方法论映射的来源与原则

- 来源：`humanity/works/`（36 本著作 verification「入库」清单 + prompts 提取）与 `humanity/synthesis/`；
- 归类标准：**指导意图（intent）/ 指导具体做法（detail）/ 指导理解用户（profiling）**——同一条方法论可以多目录出现（如「知行合一：行为证据优先」在 profiling 是证据纪律、在 intent 是原则依据）；
- 所有映射为**草稿·已审核（2026-09-30 批准）**；引用主张以对应 works verification「入库」清单为准。

## 与既有体系的关系

- `humanity/synthesis/prompts/`（P-PRO/PLAN/MOT/REV/GOV）服务于**运营期**——系统面对用户时的工作方式；
- 本目录的 P-INT/P-DTL/P-UPF 与工作流 CWI/CWD/CUP 服务于**构筑期**——我们建造平台时的工作方式；构筑期产出的意图基线、画像能力与规格，是运营期 prompt 的上游约束；
- 本目录构筑的是**元平台的生产能力**；训练计划平台（实例）是生产能力在具体需求上的展开——**阶段性产物**：因需求而生、随目标完成而归档，其执行数据回流元平台形成数据飞轮（见 docs/architecture.md §1.1）。
