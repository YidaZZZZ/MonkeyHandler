# 平台构筑：三层结构（意图层 → 细节层 → demo）

> **来源**：`humanity/refer/refer2.md`（交互系统的三层结构对话）+ `humanity/refer/用户界面交互系列工程拆解规格模板.docx`（细节层完备规格框架）。
> **构筑顺序**：意图层 → 细节层 → demo——上层为下层提供「值得性与边界」，下层为上层提供「可实现性」的反馈（合法性传递链）。
> **修订记录**：2026-09-29 创建；refer1.md 已按用户指示删除（其 17 本相邻学科书目已并入 humanity/README.md 清单）。

## 三层结构

```
values/   价值观层（使命 / 战略 / 立场伦理 / 价值主张）   ← 暂不构筑，留空目录
   └─ intent/   意图层（为什么是这个样子：五层意图结构 + 推导链 + 三张表）
       └─ detail/   细节层（是什么：可判决的完备交互规格，S/R/C/ST + E/F/P）
           └─ demo（可运行的最小纵向切片，挂质量门禁验收）
```

- **意图层**回答「为什么是这个样子，而不是另一个样子」——规格是判决性的，意图是解释性的；意图必须能追溯到事实、能被冲突检验、能被数据证伪。
- **细节层**回答「做成什么样子」——两个合格执行者（人或模型）拿同一份文档能实现出可观察行为等价的产品；形容词一律改写为指标。
- **价值观层**（使命/立场/伦理/价值主张）规定意图层的「值得性与边界」——**本平台暂不考量**，`values/` 仅保留空目录占位。
- 另有一条**约束线**（物理/技术平台/法规/组织/生态）——意图必须在其内成立；落到本平台即：性能预算、WCAG 目标等级、Python/技术栈现状、单人开发节奏。

## 目录用途

| 目录 | 内容 | 状态 |
| --- | --- | --- |
| `intent/` | 意图层元素框架 + 著作方法论映射 + 构筑指导 prompt（P-INT-*）+ 构筑工作流（CWI） | 框架就绪，构筑未开始 |
| `detail/` | 细节层元素框架 + 方法论映射 + 指导 prompt（P-DTL-*）+ 构筑工作流（CWD，终点是 demo） | 框架就绪，构筑未开始 |
| `values/` | 价值观层——**暂不考量，留空占位** | 空 |

## 方法论映射的来源与原则

- 来源：`humanity/works/`（36 本著作的 verification「入库」清单 + prompts 提取）与 `humanity/synthesis/`（因素网/工作流/Prompt 库）；
- 归类标准：**该方法论指导的是「为什么这样设计」（意图层），还是「具体怎么做成什么」（细节层）**——同一条方法论可以两层都出现（意图层给原则与置信度，细节层给字段与阈值），映射表中会显式标注；
- 所有映射均为**草稿·待审核**；引用的著作主张一律以对应 verification.md 的「入库」清单为准。

## 与既有体系的关系

- `humanity/synthesis/prompts/`（P-PRO/PLAN/MOT/REV/GOV）服务于**运营期**——系统面对用户时的工作方式；
- 本目录的 P-INT-*/P-DTL-* 服务于**构筑期**——我们建造这个平台时的工作方式；构筑期产出的意图基线与规格，是运营期 prompt 的上游约束。
